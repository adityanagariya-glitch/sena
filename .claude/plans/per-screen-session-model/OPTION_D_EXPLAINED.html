📒 The one-line idea

Today, when the AI saves something, the tool replies "ok done".
Option D: the tool replies "ok done, AND here's the new full picture."

The "new full picture" is the freshest copy of all the participant's data. The AI now reads from that, not from the (stale) copy it was given at the start.

How to read the yellow notes (the AI's memory):
red highlight = stale data
green highlight = fresh data
orange = two conflicting values for the same thing

What actually changes in code

  1. Tool reply gets richer. Today it returns {"ok": true}. We make it return {"ok": true, "state": <the full fresh form>}.
  2. System prompt loses the frozen JSON. Right now the prompt has a big __TURN_JSON__ block baked in at session start. We delete it (or shrink to just "step name + participant name"). No more stale copy.
  3. Prompt §1 gets one new sentence: "Your source of truth is the state field in the most recent tool reply."

That's it. About one day of work. No reconnect tricks. No new Gemini features. Works on the model SENA already uses (gemini-3.1-flash-live-preview).

Why not the other options?

Option A — just delete the frozen JSON

Stops the conflict, but the AI has NO snapshot on first turn. It would have to call a tool just to learn what's already filled. Confusing for the participant on turn 1.

Option B — reconnect a new Gemini session per screen (the big PLAN #1)

Works, but takes 15 subtasks. Also doesn't help within a screen if a field changes from the mobile UI. Solves a different problem (prompt size / model adherence).

Option F — push fresh JSON every turn via "system role" message

This is the most common community advice online. It DOES NOT work on Gemini 3.1. The model returns error 1007 after the first turn. Confirmed by LiveKit's official Gemini plugin docs.
