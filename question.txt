schema = JSON describing form structure for the voice agent. NOT an API. It's a field in the request body of POST /session.
What schema is
Tells Gemini: "here are the fields, ask user to fill them." Service has zero pre-stored forms — app sends the structure inline each session.
Example for step 1 (personal info):
{
  "step_id": "personal_information",
  "title": "Personal Information",
  "sections": [
    {
      "section_id": "basics",
      "title": "Basic Details",
      "fields": [
        {"field_id": "full_name",     "label": "Full Name",     "type": "text",  "required": true},
        {"field_id": "date_of_birth", "label": "Date of Birth", "type": "date",  "required": true},
        {"field_id": "phone",         "label": "Phone",         "type": "phone", "required": true}
      ]
    }
  ]
}
When AI captures full_name = "John Smith" → server emits field_updated event with section: "basics", field: "full_name" → Flutter maps that to existing form field → updates UI.

Request/response models needed
Domain entities:
VoiceSession (sessionId, wsUrl, expiresAt)
VoiceFormState (values map, completion progress)
VoiceFieldUpdate (section, field, value, confidence)
VoiceEvent sealed class (Ready/UserSaid/AgentSaid/FieldUpdated/StateUpdate/StepCompleted/Escalated/Error)
StepSchema (the structure above — entity + model)
Models = JSON ↔ entity for each.
Mapping problem
Voice service uses its own field IDs (e.g. basics.full_name). SENA onboarding uses its own draft model fields (e.g. step1Draft.fullName). Need a mapping table per step:
voice "basics.full_name" ↔ SENA step1Draft.personalDetails.fullName
voice "basics.date_of_birth" ↔ SENA step1Draft.personalDetails.dateOfBirth
Bidirectional: voice → fills SENA controller; SENA existing values → pre-fill voice state via PUT.
